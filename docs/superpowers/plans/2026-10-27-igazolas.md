# Igazolás beküldése (szülő) – Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A szülői fiók a Hiányzások oldalról igazolást (TMGI kérelem) küldhet be, és látja a korábbiakat.

**Architecture:** `folio_kreta_api`-ban tiszta modellek + egy tiszta `buildTmgiBody` függvény (unit-tesztelve), egy `CaseProvider` (ChangeNotifier, `MessageProvider` mintára) a hívásokhoz; `folio_mobile_ui`-ban egy Igazolások lap és egy űrlap. A kamu KRÉTA szerver kiszolgálja az új hívásokat.

**Tech Stack:** Flutter/Dart (provider, i18n_extension), Python stdlib (kamu-kreta).

**Spec:** `docs/superpowers/specs/2026-10-27-igazolas-design.md`

## Global Constraints

- Csak `Role.parent` fióknál látszik bármi ebből (gomb, lap).
- POST body mezőnevek és értékek pontosan a spec `TmgiCasePostDto` blokkja szerint; `tipusKod` = `"TMGI"`; dátum `yyyy-MM-dd`.
- A `tipus` a `GET adatszotarak/kerelemtipusok` válaszából a `kod == "TMGI"` elem; az `igazolasTipus` a `GET adatszotarak/tmgiigazolastipusok` válaszából választott elem – egyik sincs a kódba égetve.
- Fájlcsatolás nincs; `kerelemKotelezoDokumentumLista` és `csatolmanyok` mindig `[]`.
- Valódi KRÉTA-hoz tesztből semmit nem küldünk; minden telefonos teszt kamu KRÉTA-val (`--dart-define=KAMU_KRETA=true`, split arm64 build, versionCode 2004).
- Szövegek magyarul (+ en kulcs a meglévő `.i18n.dart` mintára), Tinta-témák színei (`Theme.of(context).colorScheme`), Outfit font öröklődik.
- Barátok nevei soha nem kerülnek kódba/commitba.

## Review Focus

- KRÉTA hibát ad vissza a POST-ra (nem 2xx, vagy `{"hibakod":..,"uzenet":..}` 200-zal) → a felhasználó a KRÉTA üzenetét látja, nem „sikeres”-t. (Task 2 teszt: `parseSubmitError`.)
- Kezdő dátum későbbi mint a záró → Küldés gomb tiltva. (Task 1 teszt: `isValidRange`.)
- A `kerelemtipusok`-ban nincs TMGI elem (az iskolánál nincs e-ügyintézés) → érthető üzenet „Ennél az iskolánál nem érhető el az igazolás”, nincs crash. (Task 2 teszt: `findTmgiType` null.)
- `gyerekemadatok` hiányos (null `oktatasiAzonosito`) → a body-ban `null` marad, mint a hivatalos appban (`toString` csak ha nem null). (Task 1 teszt.)
- `ugy/kerelmek` lista elemeiben hiányzó/null mezők (`statusz`, dátumok) → a lista nem omlik össze, „–” jelenik meg. (Task 1 teszt: `JustificationCase.fromJson` minimális JSON-nal.)

**Interfaces:**

- Produces:
  - Végpontok: `tmgiTypes = "/api/v1/adatszotarak/tmgiigazolastipusok"`, `caseTypes = "/api/v1/adatszotarak/kerelemtipusok"`, `childData = "/api/v1/kreta/gyerekemadatok"`, `cases = "/api/v1/ugy/kerelmek"` (GET és POST ugyanaz); `KretaAPI.tmgiTypes / caseTypes / childData / cases`.
  - `KretaType? findTmgiType(List<KretaType> types)` (top-level, `code == "TMGI"`)
  - `String? parseSubmitError(dynamic response)` (top-level): `null` ha siker; ha Map és van `hibakod` vagy `uzenet` / `Message` → az üzenet szövege (vagy a hibakód); ha a response `null` → `"Nem sikerült elérni a KRÉTA-t."`
  - `class CaseProvider with ChangeNotifier { CaseProvider({required BuildContext context}); List<JustificationCase> get cases; List<KretaType> get justificationTypes; bool get loading; String? get error; Future<void> load(); Future<String?> submit({required KretaType justificationType, required DateTime start, required DateTime end, String reason}); }`

    - `submit(...)`: `postAPI(KretaAPI.cases, json: true, body: jsonEncode(buildTmgiBody(...)), headers: {"content-type": "application/json"})`, majd `parseSubmitError`; siker után `load()`; visszaadja a hibaszöveget vagy `null`-t.
