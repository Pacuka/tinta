# Igazolás 2. kör – csatolás, részletek, döntés, hiánypótlás – Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans. Checkbox steps.

**Goal:** A hivatalos szülői app teljes igazolásos (e-Ügyintézés TMGI) tudása a Tintában.
**Architecture:** Az 1. kör `justification.dart` / `case_provider.dart` / `justification/` UI bővül; minden KRÉTA-alak tiszta függvényben, unit-tesztelve; kamu KRÉTA bővül.
**Tech Stack:** Flutter (image_picker, file_picker, open_filex, path_provider – már függőségek), Python stdlib.
**Spec:** `docs/superpowers/specs/2026-10-27-igazolas-design.md` („2. kör” szakasz)

## Global Constraints
- Az 1. terv minden Global Constraint-je érvényes (csak szülő, valódi iskolához semmi, magyar szöveg, barátnevek nincsenek).
- Kötelező dokumentum azonosító (`codeToUpload`) a típus `kod`-ja szerint: `ORVOSI`→36, `HIVATALOS_TAVOLLET`→39, `SZOLGALTATOI`→40, `KIKERO`→41; más kód → nincs kötelező.
- Feltöltés: `POST {kretaAdmin}/ideiglenesfajlok`, multipart, part neve `fajl`, filename URL-kódolva; válasz `fajlAzonosito` (vagy `fajlId`), `fajlMeretByteLength`, `utvonal`.
- Kötelező dok. a body-ban: `{"fajlNev", "fajl": {"ideiglenesFajlAzonosito"}, "tipus": {"azonosito": "<codeToUpload>", "rovidNev", "nev", "leiras"}}` (a kiválasztott igazolás-típus rovidNev/nev/leiras-ával); egyéb: `{"fajlNev", "fajl": {"ideiglenesFajlAzonosito"}}`.
- Hiánypótlás: `POST ugy/kerelmek/{ugyId}` body `{"azonosito", "tipus", "tipusKod", "csatolmanyok": [egyéb-alak], "statusz"}` (tipus/tipusKod/statusz az ügy saját értékei).
- Állapot-kódok: `UJ` „Feldolgozásra vár”, `FOLYAMATBAN`, `HIANYPOTLAS*` „Hiánypótlás szükséges”, `ELFOGADVA`, `ELFOGADVA_MODOSITASSAL`, `ELUTASITVA`, `LEZART`; ismeretlennél a KRÉTA `nev`-e.
- Nyomtatható: `GET {kretaAdmin}/api/v1/dokumentumok/kerelmek/{iktatottKerelem.azonosito}`, döntésé `.../dokumentumok/hatarozatok/{iktatottHatarozat.azonosito}`.

## Review Focus
- Feltöltés közben Küldés → tiltva amíg minden feltöltés kész (Task B teszt: `canSubmit`).
- Kötelező típusról nem-kötelezőre váltás → a kötelező csatolmány nem megy ki a body-ban (Task A teszt).
- Feltöltés hibája → az elem „újra” állapotban marad, nem kerül a body-ba (Task A teszt `buildTmgiBody` csak `uploaded` elemekkel).
- Hiánypótlás csatolmány nélkül → tiltva (Task A teszt `canSubmitRectification`).
- Ügy-részletek hiányos JSON → nem omlik össze (Task A teszt `CaseDetail.fromJson({})`).

### Task A: Modellek (tiszta Dart, tesztelve) — `justification.dart` + `folio/test/justification_test.dart`
- `int? mandatoryDocTypeId(String kod)` a fenti táblával.
- `class UploadedFile { String name; String tempId; }` + `UploadedFile? parseTempFile(dynamic json, String name)` (`fajlAzonosito ?? fajlId`).
- `buildTmgiBody(... , UploadedFile? mandatory, List<UploadedFile> others = const [])` → kötelező csak ha `mandatoryDocTypeId(justificationType.code) != null`; listák a fenti alakban.
- `bool canSubmit({required bool rangeOk, required KretaType? type, required bool hasMandatory, required bool uploading})`.
- `KretaType` `==`/`hashCode` (`code` + `id`) – a lenyíló assert ellen.
- `class CaseDetail` (`fromJson`): alap `JustificationCase` mezők + `stateCode`, `handlerName` (`ugyintezo.nev`), `studentName`, `educationId`, `sent`, `mandatoryDocs`/`otherDocs` (név + `utvonal`/azonosító), `filedId` (`iktatottKerelem.azonosito`), `decisions: List<Decision>` (`dontes.kod/nev`, `hatarozatDatum`, `dontesSzovege`, `indoklas`, `alairoKretaAzonosito`, igazolt időszak, `iktatottHatarozat.azonosito`), `needsRectification` (állapot vagy döntés kódja `HIANYPOTLAS*`), `raw` (az eredeti map a hiánypótláshoz).
- `String stateLabel(String? kod, String? fallback)` a fenti táblával.
- `Map buildRectificationBody(CaseDetail c, List<UploadedFile> files)`; `bool canSubmitRectification(files, uploading)`.
- Tesztek a Review Focus pontjaira + body-alakok kulcsonként.

### Task B: Kliens + provider
- `KretaClient.uploadFile(String url, {required List<int> bytes, required String fileName})` → `http.Response?` (multipart `fajl`, auth/UA/apiKey fejlécek mint `postAPI`-nál). A régi, félkész `postAPI`-multipart ág nem változik.
- `KretaAPI.caseDetail(id)`, `signer(caseId, kretaId)`, `printableCase(id)`, `printableDecision(id)`, `uploadTemp` (= meglévő `uploadAttachment`).
- `CaseProvider`: `bool includeClosed` (+ `setIncludeClosed`), `load()` → `cases?isLezartakIs=true` ha be van kapcsolva; `Future<UploadedFile?> upload(bytes, name)`; `submit(..., mandatory, others)`; `Future<CaseDetail?> loadDetail(id)`; `Future<String?> signerName(caseId, kretaId)`; `Future<String?> submitRectification(CaseDetail, files)` (ugyanaz a `parseSubmitError` + bizonytalan-ág); `Future<File?> download(url, name)` (temp könyvtárba, `getAPI(rawResponse)` bytes).
- Elhalasztott minorok: `_send` dupla-koppintás őr; „beküldve” azonnal, lista-frissítés utána.

### Task C: Kamu KRÉTA (kreta-dev)
- Valódi típuskódok (`HIVATALOS_TAVOLLET`, `PALYAVALASZTASI_CELU`, `HAZIRENDBEN_ROGZITETT_EGYEB`, ...).
- `POST /api/v1/ideiglenesfajlok` (+ régi `/ideiglenesfajlok`) → `{"fajlAzonosito": "kamu-<n>", "fajlMeretByteLength", "utvonal"}`, a fájl a `naplo/`-ba mentve.
- `GET ugy/kerelmek/{id}` részletek; egy előre beállított kamu ügy `HIANYPOTLAS_UZENETTEL` döntéssel; `POST ugy/kerelmek/{id}` naplóz és „Hiánypótlás beküldve” állapotra vált; `GET ugy/alkalmazott/{a}/{b}` → `{"nev": "Kamu Ügyintéző"}`; `GET dokumentumok/kerelmek/{id}` és `.../hatarozatok/{id}` → kis PDF.
- unittest minden új útvonalra.

### Task D: UI – űrlap csatolással
- Típus kiválasztása után: kötelezőnél „Kötelezően csatolandó dokumentum” kártya (1 db), minden típusnál „Egyéb csatolt dokumentumok” (több); „Új dokumentum csatolása” → lap: Fotó (kamera), Kép (galéria), Fájl (PDF/kép). Elem: név, állapot (feltöltés… / kész / hiba – Újra), törlés megerősítéssel.
- Küldés `canSubmit` szerint; ha kötelező hiányzik és rányom: „A kérelemhez kötelező dokumentumot csatolni.”; megerősítés kiegészül „A beküldés után a kérelem már nem módosítható.”; kilépés kitöltött űrlapról → megerősítés (`PopScope`).

### Task E: UI – részletek, döntés, hiánypótlás, lezártak
- Lista: állapot `stateLabel` szerint; „Lezártak is” kapcsoló; koppintás → `JustificationDetailPage`.
- Részletek: a spec 2.2 mezői; csatolmány/nyomtatható → letöltés + `OpenFilex.open`; döntés-kártyák (eredmény, dátum, szöveg, aláíró neve `signerName`-mel).
- `needsRectification` → „Hiánypótlás beküldése” gomb → csatolás (ugyanaz a widget) + megerősítés → `submitRectification`.

### Task F: Telefonos teszt (kamu)
- Kép + PDF csatolás (Orvosi: kötelező nélkül tiltva), beküldés → napló body; részletek; kamu hiánypótlás beküldése; lezártak kapcsoló. Képernyőképek kicsiben.
- Utána: végső review (opus), javítások, ledger, memória.
